# 河图小说规划

先通过河图稳定CLI/MCP发现活动插件 `org.wordflowlab.novel-planner`、包摘要、实际动作和本次作品的精确 `management_ref`。使用当前Schema，检查调用外层及内层结果。Skill提供创作方法，不增加作品、采纳或定稿权限。

## 选择入口

| 作品与目标 | 处理路径 |
| --- | --- |
| 已有正文，希望继续全书 | 先读[既有小说复盘](references/existing-novel.md)，再读[分层推进](references/progression.md) |
| 新书构思或只有作者原有大纲 | 从已知主张和现有大纲出发，按[分层推进](references/progression.md)建立备选方案 |
| 仅补写、返工某章或展开某卷 | 读取固定节点、祖先规划及所需前文；复用有效复盘，不强制重读整书 |
| 已有章纲，需要起草或返工 | 先检查[正文接续](references/continuation.md)，沿宿主固定任务与原稿继续 |
| 查找、修改、移动、归档、比较、导出，或维护人物／关系／伏笔和工作记录 | 读[功能操作导航](references/operations.md)，只执行与本次目标相关的操作 |

需要跑通完整插件旅程时，先读功能操作导航中的交付检查，再按作品状态选择创作路径；不要求普通局部任务执行全套功能。每次调用以本次发现的Schema为准，方法中的动作名用于定位，不代替实际可用性检查。

正文事实、Agent推断、作者原有意图和未来建议分别说明。“从成文反推的结构”不能称为作者原来的规划。目录对齐只能证明结构覆盖，不能证明通读、理解或全书规划完成。

## 保存与交付

使用稳定节点ID；复盘方案与未来方案分别保存，不把未来设想混成已经发生的事实。复盘的章详情关联确切文档修订，逐级汇总时保留证据范围、未读范围及疑问。规划以总纲约束卷纲、卷纲约束章纲、章纲约束场景节拍，但根据作者目标和实际风险逐层展开，不先穷举整本书每一场。

详情保存后按固定引用接入方案；分页读取直至 `next_cursor=null`，空页不代表结束。中断保留原输入、原键和待接入成果；未知先回读，冲突比较后再合并。工作记录区分Agent分析报告与Core保存回执，不能由保存成功推断分析质量。

交付时给出固定方案／节点／详情引用、覆盖范围、变化、待决定项及下一步。准备续写只建立参考稿，不自动采纳正文；续写后的复盘只吸收作者实际采用的版本。

## 方法资源读取

从宿主加载本Skill时，引用资源通过同包 `skills.read` 读取，传相同 `skill_id` 和相对路径，如 `references/existing-novel.md`。从Codex本地Skill目录加载时，直接按本目录解析相对路径。不要把河图资源路径当成本机任意文件路径；包停用或升级后重新发现。

剧情方向比较、双时间线和人物知情状态使用 [连续性方法](references/continuity-v2.md)。
