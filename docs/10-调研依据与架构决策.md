## 2. 上游事实与采用范围

DSH的vendor说明记录源码纳入、作用域改名和本地差异；@deepseek-ai/cordis是其维护分支，并非上游cordis的无差异别名。工具还依赖DSH的注册、取消、结果、服务和客户端合同。选同一基础框架不能自动兼容这些能力。

DSH第一插件教程使用apply／inject，生命周期教程覆盖effect／dispose；客户端模块另有入口、UI服务、远程调用与开发刷新。河图借鉴职责划分，由自己SDK保留边界；不把DSH Context直接暴露为河图公共协议。

MIT允许使用、修改与再分发，须保留许可及版权。首选上游精确锁定，暂不Fork；出现实际阻断再评估维护固定源码。npm来源快照不是发行依赖，需原型、锁文件、打包及平台验证后冻结。

## 3. 架构决策

| 决策 | 内容 | 理由及重审条件 |
| --- | --- | --- |
| NADR-01 | 河图原生插件，Codex经河图机器入口操作 | 避免双重安装／授权；只有明确跨宿主产品目标才重审 |
| NADR-02 | 宿主内部Cordis，插件公共合同仍归河图SDK | 框架可替换且作品格式稳定；不创建第二容器 |
| NADR-03 | TS领域与后端、React视图、JSON／Markdown数据 | 开发者可用常规Web工具；Rust保留确定性Core |
| NADR-04 | 单结构聚合＋分节点详情＋故事网络＋工作记录 | 兼顾结构事务和长篇规模；跨对象分步恢复，不假设多对象事务 |
| NADR-05 | 固定附件引用形成可复现组合成果 | 防止旧方案被详情新头静默改写；接入失败保留旧快照 |
| NADR-06 | 完整首版覆盖专业规划与宿主接续 | 连续创作才能验证价值；工作分批不削减正式发布门槛 |
| NADR-07 | 正式设定／正文／作者决定不复制 | 保留唯一Owner；候选、规划用途与正式来源分开 |
| NADR-08 | 每次专业动作一个权威save，原键查询先行 | 适配真实Core单对象事务；多对象事务需另立合同 |
| NADR-09 | 进度按事实回传，停止请求与取消结果分开 | 不内置第二Agent，不伪造执行或费用证明 |
| NADR-10 | DSH兼容由宿主独立分级验证 | 本包不因Cordis宣称兼容，也不依赖该兼容层发行 |
| NADR-11 | 不建设独立数据库／账号／模型／支付服务 | 复用宿主，保持插件可卸载和作品可退出 |
| NADR-12 | 完整功能地图由插件自己维护 | 宿主只维护发现和公共接入，不复制专业清单 |

## 4. 风险与应对

| 风险 | 应对与验收 |
| --- | --- |
| 首版变成孤立表单 | 按完整旅程和11必需项验收，缺宿主桥接阻断发布 |
| 单JSON超过长篇与传输预算 | 分节点详情、有界结构、固定分段导出及实测，不截断 |
| 分对象造成半完成或丢关联 | 保存与接入分别有原键、状态和回读，待接入成果可恢复 |
| 专业原输入幂等不充分 | 补宿主输入指纹合同；未补前保守拒绝歧义，不虚假承诺 |
| 通用保存绕过专业语义 | 专业读取同样校验，保留坏修订并诊断 |
| 框架或DSH服务侵入公共数据 | 普通TS领域和SDK隔离，框架对象不持久化；版本升级回归 |
| 正文／设定双份事实 | 固定来源与独立宿主方案，规划备注不伪装正式修改 |
| 成本价值只依赖Token价格 | 同质量任务测时间、模型实际用量、操作负担与恢复；长期价值是作品接续 |

Cordis 生命周期、独立插件与真实机器／桌面旅程分别取证，运行结果以08为唯一记录。公开研究不证明 DSH 跨生态兼容、Token 节省或其他平台性能；未执行的平台不作通过结论。产品 README 不复制动态验收统计。
