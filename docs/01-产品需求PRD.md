# 产品需求PRD

## 1. 产品定义与背景

小说规划是河图的专业创作插件，帮助作者与外部Agent围绕整部小说组织总纲、卷章安排、冲突、转折和状态变化。作者表达目标，Agent整理与修改，河图呈现可阅读、可比较、可追溯的成果。

长篇创作的困难在于局部变化与整书结构相互影响。Markdown适合自由表达，结构化数据适合引用、排序、预算和局部操作；两者共存。产品不要求作者填写JSON，也不要求把创作压成固定模板。

## 2. 第一性原理推导

1. 创作意图开放，模型适合理解与生成；它不能代替作者的品味和取舍。
2. 同一部作品持续变化，需要稳定身份、来源、修订及操作恢复，单轮回答难以独立承担这些事实。
3. 顺序、层级、预算、版本冲突与结构校验适合确定性软件执行，复用代码可减少重复解释与生成。
4. 作者需要阅读整体、检查细节和表达意见；可视化承担理解与审阅，机器动作承担重复操作。
5. 专业能力按需分发，宿主保持共同作品规则，可减少非目标用户的操作负担。

Token价格和生成速度是当前成本变量，不能作为唯一生存理由。长期价值是作品积累、可执行结构、反馈接续和退出能力。成本收益需在等质量任务中测量，不能从JSON字节数推断节省多少Token。

## 3. 用户与默认旅程

| 用户 | 需求 | 产品支持 |
| --- | --- | --- |
| 初次规划作者 | 从模糊构想到可审阅结构 | Codex引导，保存完整方案，逐层阅读 |
| 长篇连载作者 | 只调整一卷，保护既定结局与其他内容 | 明确范围、稳定节点、局部动作、修订比较 |
| 偏好手写的作者 | 自由文字并保留人工调整 | Markdown说明与可选编辑，统一保存规则 |
| 编辑或共同审阅者 | 看清依据、差异和未解决问题 | 固定成果、版本对比与意见交接 |
| 插件开发者 | 无需理解Rust内部即可扩展 | TS领域模块、河图SDK与独立文档 |

默认链路：作者向Codex提出目标→河图CLI/MCP发现与读取→插件执行确定性动作→Core保存→Agent回读→作者在河图审阅→沿固定成果返工。桌面关闭时前半段仍可执行。

## 4. 首版功能需求

功能ID及动作导航只在[功能清单](../CAPABILITIES.md)定义，以下规定验收语义。

| 功能 | 必须达到的行为 |
| --- | --- |
| NP-01／02 | 分页列方案，读取整书摘要、卷章层级及固定节点；同名节点不合并 |
| NP-03 | 一次提交完整有效方案，新建与更新有明确CAS，备选方案独立 |
| NP-04／05 | 按节点ID及明确字段修改或新增，保护未列范围；不创建正式章节 |
| NP-06／07 | 顺序及父子关系一致，归档保留后代与历史，恢复不丢字段 |
| NP-08 | 结构错误阻止业务写入；创作完整性建议可以保留，不声称保证故事质量 |
| NP-09 | 比较两个固定修订，显示新增、移位、归档和字段变化，不自动覆盖当前方案 |
| NP-10／11 | 固定内容导出、原操作查询及恢复；不得将写文件或外发藏在只读动作中 |
| NP-13～26 | 完整卷章资料、长篇剧情、实体／伏笔／关系、真实工作记录、固定组合成果和宿主接续，逐项满足11的规格 |
| NP-12 | 阅读优先、可选编辑、状态明确；复制交接与Agent受理分别显示 |

## 5. 范围与非功能要求

首版范围按[首版功能规格](11-首版功能规格与发布门槛.md)执行，包括整书→卷→章、副标题与规划状态、概要／开局／目标／主题／冲突／转折／起止状态、章节与字数预算、长篇详细剧情和节拍；同时覆盖卷内实体、五类规划卡、伏笔追踪、关系图表、回收站、版本比较、AI交接、真实工作步骤与正式章节接续。

这些能力必须形成连续创作流程，不能只有孤立表单或空Tab。章节正文和正式设定仍归宿主，插件通过首版必需的类型化集成读取、打开或准备确定方案；不建立第二份正典。正式大纲应用、正文采纳及定稿使用宿主独立方案，不随规划保存自动执行。

不包含内置Agent、聊天、模型重连循环、自动采纳正文、独立账号、支付、同步或三维编辑器。关系图与等价关系表属于首版，作者不必亲自拖连线；可视化服务阅读与Review。不同渲染形式可以扩展，不削减首版的专业创作信息。

| 要求 | 约束 |
| --- | --- |
| 可靠性 | 单方案事务、CAS、原键恢复；冲突和unknown保留输入 |
| 隐私 | 精确作品与包授权；不直接读取任意路径，不默认联网 |
| 可携带 | JSON保留完整字段，专业Markdown可读；缺插件仍可宿主通用导出 |
| 中文体验 | 中文长内容、组合输入、键盘及窄窗可用；浅暗主题与无障碍降级 |
| 性能 | 节点及字节预算明确；节点读取避免重复回传整书；响应指标在基准确定后实测 |
| 可维护 | Schema、动作、功能清单、文档和验收联动；框架对象不进入作品 |

## 6. 成功与限制

以“指定一卷调整后，其余范围保持，Codex与GUI读到同一修订，作者可理解并继续”为首个完整用例。记录任务时间、模型实际用量、主动操作次数、失败恢复和作者评价。当前没有用户研究或运行数据，不预设满意度、性能或成本节省比例。

它是开发纵切验收，不是首版全部范围。正式首版还必须通过11中的整书分卷、篇章与详细剧情、实体／伏笔／关系、进度停止、正文接续和完整异常旅程；宿主缺口同样属于发布阻断。
