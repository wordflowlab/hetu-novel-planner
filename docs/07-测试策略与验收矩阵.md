# 测试策略与验收矩阵

## 1. 验收方法

以[05](05-用户故事与业务流程.md)的有限等价类覆盖常规、权限、并发、故障及退出。测试首先证明关闭桌面后，外部Agent仍能经河图完成业务；随后证明作者在GUI看到同一固定成果。源码阅读、Schema合法、图表渲染和模拟Core测试分别有价值，但都不能替代真实Core／CLI／MCP验收。

使用隔离的演示小说及固定包，保留动作、包摘要、完整WorkRef、基线、操作键和成果修订。记录脱敏输入摘要、预期、实测及命令退出码；授权数据不写入公开仓库。不得为制造通过而直接写`.hetu`或绕过公开入口。

## 2. 分层验证

| 层次 | 覆盖 | 证据边界 |
| --- | --- | --- |
| 文档与合同 | 链接、JSON、Schema、样例、Mermaid、功能／用例映射 | 不执行插件与Cordis |
| 领域单元 | 树变换、字段白名单、语义、预算、差异、Markdown导出 | 不证明Core业务规则与事务 |
| 应用与SDK | 固定版本读取、确定性save、内外层Result、故障与buffer | 替身结果不等于真实Core |
| 真实Core及CLI | 安装、授权、发现、全部专业动作、CAS、原操作与退出 | 无窗口完成主纵切 |
| MCP | 同一包、同一作品经稳定工具调用，动态更新及失效 | 不能只调用CLI后宣称MCP通过 |
| GUI | 同版本阅读／编辑／比较，IME、恢复、主题与异常 | 视觉检查结合行为、键盘与样式断言 |
| 发布与平台 | 预构建包、精确依赖、离线读取、macOS／Windows | 每个平台独立取证，未跑不宣称通过 |

## 4. 必要故障与性质断言

树变换使用原创演示数据及生成的合法树，断言节点守恒、唯一父级、有序性与变换确定性。每个无效变换拒绝后原输入不变。JSON Schema不能发现的跨字段错误须直接覆盖，不能只测试与实现同形的happy path。

在Core提交前、提交后回执前、插件超时、MCP传输失败、停用及重启之间注入故障。真实宿主层暂不支持的注入需明确记录缺口，不将模拟测试记为实测。外层invoke成功而内层失败必须在CLI、MCP和GUI三处正确呈现。

首版不申请网络、子进程或任意文件能力；应验证不能通过Markdown URL、后端异常或通用request扩权。读取不写缓存或修改作品。业务测试用前后正式正文／大纲摘要证明边界，而不是仅检查规划对象存在。

## 正式安装包验收入口

`HETU_SOURCE`指向固定宿主源码checkout；`HETU_TEST_PACKAGE`指向已解压发行包；`HETU_TEST_BIN`指向随包CLI/MCP目录；`HETU_PACKAGED_APP`指向实际桌面可执行文件。安装模式关闭开发Node、Plugin Manager与App Server覆盖，实际业务使用正式随包组件。

原规划工作面与新增连续性均运行机器和Electron旅程；测试数据由隔离fixture准备，不进入作者作品。包内Skill、固定来源、原操作、冲突和生命周期分别取证，不用开发dist替代下载包。
